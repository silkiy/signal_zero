## Output and input threat boundary

- `packages/puzzle_domain/lib/src/puzzle_spec.dart`: immutable typed nodes/edges/puzzle, strict schema/version/ID/count/reference/routing validation, canonical ordering, indexes, byte identity and SHA-256 hash.
- `packages/puzzle_domain/lib/src/canonical_json.dart`: bounded raw UTF-8 JSON reader preserving duplicate-key and numeric lexical evidence, plus bounded canonical encoder. This shared primitive is reused by T010, without implementing replay or simulation in T009.
- `packages/puzzle_domain/lib/src/domain_error.dart`: structured `DomainException(code,path,message,{offset})`, extending `FormatException`; safe messages do not echo the submitted payload.
- Public exports in `packages/puzzle_domain/lib/puzzle_domain.dart`.
- `specs/puzzle-schema/v1.json`: Draft 2020-12 interchange schema, documenting runtime-only cross-object and raw lexical guards.
- `packages/puzzle_domain/test/puzzle_spec_test.dart`: 39 targeted tests.

Untrusted file/API bytes cross into bounded decode, then exact allowlisted puzzle validation. Assets protected are canonical identity correctness, deterministic graph semantics, and bounded resource use. Abuse cases include duplicate escaped/nested keys, numeric spelling changes hidden by normal JSON decoding, malformed UTF-8, depth/size exhaustion, foreign references and mutable state changing a previously hashed puzzle.

## Checks included

- Inclusive node/source/target/switch/tick/raw-byte limits and oversized-edge rejection before processing items.
- Unknown versions/fields, missing fields, illegal kind/initial state/degree/ports, duplicate IDs/endpoint pairs, foreign endpoints, source incoming/target outgoing and unequal source/target counts.
- Raw `-0`, negative/positive signs, fraction/exponent/leading zero, oversized integer, NaN/Infinity; bool/null/string where an integer is required.
- Duplicate root, nested and escaped-equivalent object keys; invalid UTF-8/BOM; root depth 16 versus 17; unsupported root/field types return domain errors instead of runtime casts.
- Escaped ASCII IDs canonicalize to literal ASCII; non-ASCII/invalid IDs and DEL in canonical values are rejected.
- Readonly typed collections, indexes, nested serialization maps/lists and canonical byte buffer; caller-owned source maps cannot mutate a model after parse.

The frozen identity fixture matches:

Additionally, local Python `jsonschema 4.26.0` validated the Draft 2020-12 schema itself, accepted all 13 rule-puzzle fixtures, and rejected an extra gameplay `title` field. The ID expression was checked against a valid ID and a trailing-newline ID. JSON Schema cannot preserve raw number spelling or express every graph cross-reference/degree condition; `PuzzleSpec.decode` is authoritative for those checks.

## Review, scope, and next consumer

Independent read-only reviews by competition_tasks and local_content_tasks found no blocking schema/parser/model issue. Outgoing lists are ordered by edge ID; the future engine must route by `edge.port`, not list position. Missing node ID currently reports `INVALID_ID` rather than `MISSING_FIELD`; the field is still rejected with a safe schema path.

`PuzzleSpec.fromJson` is for editor-owned maps. Raw imports/API data must use `decode`/`parse` so lexical/duplicate-key evidence has not already been discarded. `DUPLICATE_FIELD` is the domain error; a future HTTP adapter may map it to the API's `DUPLICATE_KEY` response code.

No solver, replay, engine, renderer, wallet, backend, generator or future-task source was implemented. This task uses three production source modules plus the barrel export; the strict raw input boundary is necessary to meet the existing T001/T002/T007 contract. T010 can now reuse `CanonicalJson`/`DomainException`; T011 can freeze puzzle bytes/hash against the reviewed manual tick oracle.
