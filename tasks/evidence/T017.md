# T017 — Solver terbatas dan bukti optimalitas

Status: **done**, 6 November 2026 (Asia/Jakarta). Implemented by solver agent; reviewed by root and properties agent.

The production engine is the only transition function. Dijkstra orders prefixes by `(SHIFT count,tick)`; transpositions retain tick, global switch parity and every source-ordered position. Only a cheaper prefix of the same state dominates. Settled parents never change, and the frontier lower bound must certify the verified incumbent before `solvedOptimal`. Complete exhaustion establishes `unsatisfiable`; budget or cancellation does not.

Fixed typed buffers contain positions, tick/parity/cost, predecessor/action, closed flags, indexed heap and open-address table. Reservation checks exact buffer bytes plus a conservative 2 MiB graph/transient/output allowance before allocating the arena. Accounting is not process RSS or a hard VM heap cap. State/transition/deadline counters are cumulative when a budget is reused; active memory reservations release in `finally`. Every candidate verification step counts against the same transition budget.

`solveAsync` initially yields and then gives the event loop a turn after at most 16 actual transitions or a 2 ms slice. A transition is bounded by puzzle limits; this is cooperative execution, not a hard real-time guarantee. CPU-heavy service work still belongs behind the worker/watchdog boundary in T007. The synchronous API is for headless tooling.
